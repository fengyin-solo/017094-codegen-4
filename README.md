# 知识配置平台 - 中后台

运营端知识配置中后台：商家知识、商家集合知识、行业知识、通用知识及商家黑名单管理。纯前端展示，数据使用 Mock + localStorage 持久化。

## 登录信息

系统启动后需要登录才能访问，默认账号密码：

| 用户名 | 密码 | 角色 | 权限 |
|--------|------|------|------|
| `user` | `123456` | 管理员 | 全部功能，可调整通用知识例外/黑名单 |
| `viewer` | `123456` | 只读用户 | 可浏览、可编辑知识内容，**不能**调整生效范围（例外/黑名单） |

## 通用知识生效范围（商家例外）

通用知识默认对所有商家、行业生效，并支持两层排除：

- **单条知识的例外商家**：在「通用知识」列表点击某条的「生效范围」，勾选不接收该条的商家。例外只影响这一条，其它通用知识仍按各自的范围分别判定；未被排除的商家共享同一份内容，不会为例外复制内容。
- **商家黑名单**：黑名单商家对**全部**通用知识整体不生效；移出黑名单后自动恢复（若仍命中某条的例外，则该条仍不生效）。

判定优先级：`黑名单（整体排除） > 单条例外（仅该条排除） > 默认生效`。归属判定由数据层统一口径（`MockStore.resolveGlobalKnowledgeForMerchant` / `getGlobalKnowledgeForMerchant`）提供，通用知识页的「生效范围」列/弹层与商家知识页的「通用知识生效情况」看到的结果完全一致。

- 配置弹层顶部直接展示「当前被排除的商家」，保存后列表「生效范围」列可看出每条生效到哪几家、例外几家、黑名单几家。
- 已配置的例外随知识独立持久化，编辑知识内容不会丢失。
- 调整例外/黑名单需要管理员权限（存储层与界面层双重校验）。

## 最终交付：Docker 启动

**唯一启动命令**（无需预装 Node 或其它运行时）：

```bash
docker compose up
```

首次运行会自动构建镜像；之后直接启动。启动成功后，控制台会显式输出：

```
==============================================
  Startup Success
  Frontend Admin: http://localhost:8080
==============================================
```

在浏览器访问 **http://localhost:8080** 即可使用中后台。如需后台运行，使用 `docker compose up -d`。

**交付验证**：在项目根目录执行 `docker compose up --build`，看到上述 "Startup Success" 与访问地址后，用浏览器打开该地址即可验收各模块功能。

## 本地开发（不经过 Docker）

在项目根目录用任意静态服务器托管 `frontend-admin` 目录，例如：

```bash
cd frontend-admin && npx serve -p 3000
```

访问 http://localhost:3000（注意：部分功能依赖相对路径 `js/`、`css/`，请以根路径打开）。

## 功能概览

| 模块         | 说明 |
|--------------|------|
| 商家知识     | 按商家筛选，对该商家下知识增删改查（标准问、相似问、答案） |
| 商家集合知识 | 新建/编辑/删除商家集合（多选商家），在集合下管理知识 |
| 行业知识     | 新增/编辑/删除行业（二级行业），在行业下管理知识 |
| 通用知识     | 全局知识增删改查；按条配置例外商家生效范围；商家黑名单（黑名单内商家整体不生效通用知识） |

## 技术栈

- HTML + JavaScript + CSS
- Tailwind CSS（CDN）
- 字体：Plus Jakarta Sans、Inter、JetBrains Mono
- 交付：Docker + Nginx
