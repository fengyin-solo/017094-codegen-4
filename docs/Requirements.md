# 知识配置平台 - 需求说明（SSOT）

## 1. 项目概述

知识配置平台的中后台管理端，面向运营人员，用于对「知识」进行增删改查及按类型、商家、行业等维度管理。当前阶段为**纯展示前端**（HTML + JS + CSS，可使用 Tailwind），不依赖后端接口，数据可本地 Mock 或静态展示。

---

## 2. 知识模型

### 2.1 基础字段

每条知识均包含以下基础字段：

| 字段     | 说明                         |
|----------|------------------------------|
| 标准问   | 标准问题表述                 |
| 相似问   | 与标准问语义相近的多种问法   |
| 答案     | 对应答案内容                 |

（展示层可扩展：ID、创建时间、更新时间等，由实现自定。）

### 2.2 知识挂载类型

知识可挂在以下四种类型下，决定其生效范围：

- **商家知识**：挂在单个商家 ID 下，仅对该商家生效。
- **商家集合知识**：挂在一批商家 ID（商家集合）下，对该集合内商家生效。
- **行业知识**：挂在某个行业 ID 下，对该行业生效。
- **通用知识**：对所有商家、行业生效；可通过商家黑名单排除部分商家。

---

## 3. 功能需求

### 3.1 商家知识

- 知识挂在**某个商家 ID** 下。
- 支持**筛选/选择已有商家**，并针对该商家进行知识的查看与编辑（增删改查）。
- 列表/详情中需能区分并展示「商家 ID」及该商家下知识条数或列表。

### 3.2 商家集合知识

- 知识挂在**某批商家 ID（商家集合）** 下。
- 支持**新建商家集合**：具备**商家选择能力**（如多选商家、按 ID/名称筛选等，具体交互由前端设计）。
- 对已有商家集合支持：查看集合信息、编辑集合内商家、以及在该集合下对知识进行**增删改查**。

### 3.3 行业知识

- 知识挂在**某个行业 ID** 下。
- 支持**新增行业**：具备**行业选择能力**，要求为**二级行业**（一级 + 二级）。
- 对已有行业支持：查看行业信息、以及在该行业下对知识进行**增删改查**。

### 3.4 通用知识

- 知识对所有商家、行业生效。
- 支持**设置商家黑名单**：黑名单中的商家不生效通用知识；需提供黑名单的增删改查或配置界面。
- 对通用知识本身支持**增删改查**。

### 3.5 通用知识按商家生效范围（个别例外）

通用知识默认对全部商家共享同一份内容，运营可对**个别商家、按条**设置例外：

- 某些商家不接收其中某几条通用知识；这几条对其它商家照常生效（仅排除指定商家，不复制内容）。
- 支持按商家为每条通用知识设置生效范围；**配置时可看到当前被排除的商家**，保存后列表中可直观看出每条**生效到哪里**（生效/例外/黑名单数量徽标）。
- 同一商家同时命中多条通用知识时，**按各自的生效范围分别决定**，条与条互不影响。
- **黑名单商家整体排除**在通用知识范围之外；加入黑名单即整体不生效，**移出黑名单后按各条例外配置恢复**（黑名单期间不丢失已配置的例外）。
- 归属/生效关系在**多个页面结果一致**：通用知识页（配置视角）与商家知识页（商家命中视角）使用同一判定逻辑。
- **调整例外需要权限校验**：仅具备 `global_scope:manage` 权限的账号可保存；无权限账号只读可查看。
- 已配置过的例外**不能丢失**：编辑知识内容、黑名单加/移出、页面切换均保留；删除知识或商家时再做对应清理。

## 4. 非功能与约束

- **技术栈**：HTML + JavaScript + CSS；允许使用 Tailwind 等现代 CSS 方案；纯展示前端，可不接真实后端。
- **交付形态**：页面需可在浏览器中直接打开或通过本地/容器内静态服务访问，满足「可访问的 Web 界面」的交付标准。
- **UI**：中后台风格，结构清晰、布局合理，便于后续对接真实 API。

---

## 5. 范围边界（当前版本）

- 以**前端展示与交互**为主：列表、筛选、表单、增删改查的页面与流程均可先以 Mock 数据或本地状态实现。
- 后端 API、持久化、权限等可在后续阶段按 Roadmap 补充；本需求文档仅定义「做什么」，不强制本阶段实现后端。
